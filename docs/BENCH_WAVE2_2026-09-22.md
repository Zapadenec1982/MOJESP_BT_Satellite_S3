Хвиля 2 зібрана й **злита** в `stage5/hardening` (87+ комітів від `080a3a3`). Образ готовий,
**не прошитий**: на панелі лишається вчорашня збірка, яку ми разом довели до робочого стану.

Цей документ — що прошити, у якому порядку перевіряти і на що дивитись.

## Прошивка: цього разу ПОВНА, і це важливо

Етап 11 переніс користувацькі файли в окрему партицію `userdata` (0xF80000). Нова таблиця
партицій означає повну прошивку, а повна прошивка ще **раз** перезапише `data` — тому файли
мусять проїхати всередині образу:

```
python tools/user_data.py backup      # ДО прошивки. Після неї їх уже немає.
python tools/user_data.py seed        # у data/, щоб data.bin їх повіз
idf.py -C D:\P4_DSP\wt\int -B D:\P4_DSP\wt\int\build -p COM12 flash
python tools/user_data.py restore     # повернути data/ у стан git
```

Після цього першого разу проблема зникає назавжди: `idf.py flash` не збирає образу для
`userdata` (перевірено по `build/flash_args` — за адресою 0xF80000 немає нічого), тож наступні
прошивки користувацькі файли не чіпають.

**Якщо прошити лише застосунок** — панель лишиться зі старою таблицею, `UserStore` відкотиться
на `/data` і скаже про це у WARN на кожному завантаженні. Не цегла, просто стара вразливість.

Спостерігати консоль **без** `idf.py monitor` (DTR смикає reset): `dtr=False`, `rts=False`.

## Порядок перевірки — за спаданням ризику

### 1. Те, що вчора не працювало (регресійний контроль)

Це перше, бо решта не має сенсу, якщо це зламалось:

- **DLNA** хвилину — без затримки, без `buffer 0%`.
- **Bluetooth** — має заграти. У рядку `BT signal` чекаємо `short 0, dropped 0, resyncs 0`.
- **Картка** — має підхопити той самий трек із тієї ж секунди.
- Ще раз по колу, у будь-якому порядку.

### 2. Клацання між треками (етап 14 — головне на слух)

Плейлист 44,1 / 48 / 44,1 з картки. Очікування:

- `output retuned to` у лозі зʼявляється **лише** при зміні джерела, ніколи між треками.
- Клацання немає. Мікрофон на межі має дати фон (~100), а не ~1000.
- Межа тепер ще й **без паузи** — плеєр більше не дренажить хвіст перед зміною.
- Треки, що не збігаються з частотою сесії, логуються як `ratio 1.0884 (fixed-ratio resampler)`.

### 3. Тактування замість ресемплера в Bluetooth (етап 13)

Рядок `BT signal` раз на 5 с тепер каже, який шлях працює:

```
BT signal: ... -> clock 48000 Hz, clock 17 ppm, asrc 0, short 0, dropped 0, ...
```

- **`clock N ppm`** (а не `asrc N ppm`) — сервопривід веде клок, ресемплер вимкнено.
- **`asrc`** рахує блоки, що все ж пройшли через конвертер. У сталому режимі **не має рости** —
  це і є DoD «лічильник ASRC-кадрів нуль», вираженим числом.
- ppm за хвилину-дві дійде до дрейфу (4–40) і завмре.
- Якщо там `asrc` — порт відмовив у тримі, і причину скаже один рядок `W` від `I2sStd`. Це
  **відкат, а не поломка**: звук такий самий, як був.

**На що слухати окремо:** тихий «тік» у моменти зміни ppm — приблизно двічі на хвилину, поки
сервопривід усідається. Це перекалібрування APLL, і це єдине, на що може відповісти лише вухо.
Якщо чутно — відкотити **тільки** `50c354d`, решта етапу стоїть без нього.

### 4. Паритет Bluetooth в інтерфейсі (етап 12)

- Назва, виконавець, альбом із телефона замість слова «Bluetooth».
- Прогресбар іде з кроком у секунду, зупиняється в паузі.
- Play / pause / next / prev керують телефоном; без звʼязку кнопки сірі й не натискаються.
- Індикатор CPU показує **число**, а не нуль (читався як int із float-ключа).
- **Нове, пункт 12.6:** щойно ви перемикаєте джерело з Bluetooth, панель шле телефону PAUSE.
  Повернення відновлює **лише ту паузу, яку поставила сама панель**, і лише якщо телефон до
  того повідомляв «граю». Ваша власна пауза з телефона не скасовується.

### 5. Памʼять (етап 7) — числа, не відчуття

У лозі завантаження:

```
main: Heap before Wi-Fi: ... DMA NNNNNN (largest NNNNNN)
main: Heap after init:   ... DMA NNNNN  (largest NNNNN)
AudioPipe: resampler 44100 -> 48000 Hz, 160 phases, built in NN ms; internal ..., DMA ...
Radio: stream heap: internal NNNNN, DMA NNNN (largest NNNN)
```

DoD етапу: **вільна DMA-internal ≥ 80 КБ, найбільший блок ≥ 64 КБ**. Учора в момент відмови
було 2535 і 2432. Найцінніше — саме `largest`: банк фільтрів ресемплера був 161 окремим
блоком по 192 байти у внутрішній купі на кожен конвертер, тепер це один блок у PSRAM.

Окремо варто перевірити **MQTT-TLS і HTTPS-радіо одночасно** — вікно TLS підняте з 4 до 16 КБ
рівно тому, що арена mbedTLS поїхала в PSRAM.

### 6. Персистенція (етап 11)

- Два послідовних `idf.py flash` **не стирають** EQ і список станцій.
- У лозі один раз має зʼявитись підсумок міграції від `UserStore`.
- Рівень логів тепер WARN, але шість тегів лишені на INFO — `main`, `ConfigSvc`, `UserStore`,
  `I2sStd`, `Audio`, `Radio` і `Bt`. Перемикається наживо через `/api/loglevel`.

## Що агенти знайшли понад план

Варте вашої уваги, бо це не те, за чим їх посилали:

| Знахідка | Чому важлива |
|---|---|
| Прогресбар у BT став би пультом перемотування **файлового** декодера | `Req::SEEK` вибирав ключ як «5 → радіо, інакше плеєр» |
| Витік мʼютекса в самому IDF (`i2s_channel_tune_rate`) | ранній `return` не віддає `handle->mutex`; стає досяжним рівно після лагодження лічильника APLL |
| Лічильник посилань APLL буває **3**, не 1 | майстер TX + майстер RX + вхід сателіта; план описував це як «одне зайве посилання» |
| `/api/state` і WebSocket різали **кожен** рядок на 63 символах | 256-байтове сховище ніколи не було видиме веб-інтерфейсу |
| `parse_image_header` у `c6_updater` рахував довжину на 16 байт більше | жодна перевірка SHA-256 образу C6 не могла зійтись |
| Хостові копії `shared_test`/`base_module` розійшлися з прошивкою | тести були зелені щодо поведінки, якої на пристрої немає; копії видалено |
| `last_dir` ніколи не існував, а `devices.json` не бекапився | гинув при кожній повній прошивці |

## Ризики, які варто тримати в полі зору

1. **Сервопривід клоку** (`50c354d`) — єдина зміна, наслідок якої може бути чутним. Відкочується
   окремо.
2. **`FREERTOS_HZ=1000`** з етапу 6 досі не пройшов соук. Ключ `system.main_loop_max_ms` доданий
   рівно для цього: якщо росте — `git revert 53717cb`.
3. **Друге монтування LittleFS** коштує ~2,5 КБ внутрішньої купи. На тлі звільнених 103 КБ це
   дрібниця, але при вимірюванні DoD етапу 7 про це треба памʼятати.
4. **`underruns` сателіта** росте ~2/с і до наших правок стосунку не має — записано як пункт
   10.10, хвиля 3.
