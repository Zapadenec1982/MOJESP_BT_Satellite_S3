# DSP v2: ланцюг, рівні, захист TPA3255 — 30.09.2026

Основа: `DSP_RESEARCH_2026-09-30.md`, три дизайни (fidelity, protection, realtime — §9), даташити
TPA3255 (SLASEA8A), PCM5102A (SLAS859C), TPA3255EVM (SLOU441). Факт замовника: PVDD 24 В, на гучному
басу підсилювач іде в захист; решта про модуль — калібрувальні параметри (CLAUDE.md, правило 2).
Числа перевірено скриптами `scratchpad/dsp_v2/judge/`.

## 1. Коротко

```
джерело → g_e (trim·гучність·стеля EQ) → сабсонік BW4 40 Гц → PEQ 10×SVF (matched) → width/mono-bass
        → бас-лімітер LR4 120 Гц → брикволл → ×k_out → I2S → PCM5102A → TPA3255
```

- **Хрипу немає:** DF2 (шум −36/−23 dB відносно сигналу на 96/192k) → SVF (−125/−114 dB).
- **Підсилювач не кліпує:** максимум цифри — точка кліпу TPA3255 (при 24 В −9.8 dBFS, §3), а не 0 dBFS
  ЦАП; сьогодні верх шкали — ~10 dB кліпу. Точно — калібруванням за 10 хв (§4).
- **Гучний бас стискається сам, середина не «дихає»:** першим поступається бас (до −12 dB), решту бере брикволл.
- **100 % = найгучніше чисте.** Та сама позиція ручки на ~10 dB тихіша — звичний рівень на ~17 % вище.
- **Без клацань** (повзунки, кнопка EQ, mute); **EQ однаковий** на 44.1 і 96/192k (розкид 1.08 → 0.23 dB).

### 2.1. Ядро SVF (блоки 2–5)

```
v3 = x - s2                                  // стан {s1,s2} на канал, коефіцієнти {c1,c2,c3,m0,m1,m2}
v1 = fmaf(c2, v3, c1*s1)
v2 = fmaf(c3, v3, fmaf(c2, s1, s2))          // НЕ згортати s2 + c3*(x - s2) у (1-c3)*s2
s1 = fmaf(2.f, v1, -s1);   s2 = fmaf(2.f, v2, -s2)
y  = fmaf(m2, v2, fmaf(m1, v1, m0*x))
c1 = 1/(1 + g*(g + k));   c2 = g*c1;   c3 = g*c2
```

- L і R в одному циклі, in place; вихід кадру i пишеться на ітерації i+1, стан у регістрах: 26 інструкцій
  на стереокадр без spill (GCC 14.2 `-O2`), модель 26–31 такт проти 46 у DF2. Звільняє 3.8 KB буферів.
- TU `dsp_kernels.cpp` з `-ffp-contract=off` і явними `fmaf`: хост і P4 округлюють однаково. Без `esp.lp`
  (esp-idf#19025); IRAM — лише якщо стенд дасть ≥ 10 % середнього.

### 2.2. Коефіцієнти

Усе в double, зберігається у float. Власник — аудіозадача: ≤ 1 дизайн на блок, на `retune()` — усі при
закритій огинаючій. UI кличе ту саму функцію і малює |H| замкненою формою (дослідження §4.1).

**Білінійний** (LP/HP-смуги, сабсонік, side-HP, LR4, запасний): `A = 10^(dB/40)`, `g = tan(πf/fs)`,
`k = 1/Q`; PEAK `k = 1/(QA)`, m = (1, k(A²−1), 0); LOW_SHELF `g /= √A`, m = (1, k(A−1), A²−1);
HIGH_SHELF `g *= √A`, m = (A², k(1−A)A, 1−A²); LP (0,0,1); HP (1,−k,−1); NOTCH (1,−k,0); AP (1,−2k,0).

**Matched** (PEAK, полиці, NOTCH; Vicanek): полюси імпульсною інваріантністю, |H| = аналоговий
прототип RBJ на DC, f0 і Найквісті:

```
w0 = 2π·f0/fs;  (wp, ζ) = PEAK (1, 1/(2AQ)) | LS (1/√A, 1/(2Q)) | HS (√A, 1/(2Q)) | NOTCH (1, 1/(2Q))
W = w0·wp;  e = exp(−ζW);  a2 = e²;  a1 = −2e·cos(W√(1−ζ²)) при ζ ≤ 1, інакше −2e·cosh(W√(ζ²−1))
NOTCH: n = (1+a1+a2)/(2−2cos w0);  (b0,b1,b2) = n·(1, −2cos w0, 1)  → to_svf
Ha: PEAK (s²+sA/Q+1)/(s²+s/(AQ)+1);  LS A(s²+s√A/Q+A)/(As²+s√A/Q+1);  HS A(As²+s√A/Q+1)/(s²+s√A/Q+A);  s = j·f/f0
A0 = (1+a1+a2)²;  A1 = (1−a1+a2)²;  A2 = −4·a2
wm = min(w0, 0.9π);  φ1 = sin²(wm/2);  φ0 = 1−φ1;  φ2 = 4·φ0·φ1
B0 = A0·|Ha(0)|²;  B1 = A1·|Ha(fs/2)|²;  B2 = (|Ha(wm·fs/2π)|²·(A0φ0+A1φ1+A2φ2) − B0φ0 − B1φ1)/φ2
V = (√B0+√B1)/2;  b1 = (√B0−√B1)/2;  якщо V²+B2 < 0 → білінійний
b0 = (V + √(V²+B2))/2;  b2 = V − b0
to_svf: d = 1−a1+a2;  g = √((1+a1+a2)/d);  k = 2(1−a2)/(d·g)
        m0 = (b0−b1+b2)/d;  m1 = (2(b0−b2)/d − m0·g·k)/g;  m2 = (b0+b1+b2)/(d·g²) − m0
```

- Хост (відтворено): EQ замовника проти аналогу 1.14 → 0.24 dB на 44.1k; розкид 44.1…192k 1.08 → 0.23 dB;
  найгірший пресет 2.04 → 0.93 dB (44.1k), 1.67 → 0.62 (48k).
- Пресети перепідганяє `tools/eq/fit_presets.py`; Q полиць ≤ 1.0 (прихований горб +15.6 dB при Q 8).
- Double-дизайн — оцінка 20–60 тис. тактів; > 100 тис. на стенді → ядро 0 з міткою fs в `eq_bus`.

### 2.3. Зміна параметрів

Кросфейд двох фільтрів: `N = round(0.020·fs)`, `t = n/N`, `w = t²(3−2t)`, `y = fmaf(w, y_new − y_old, y_old)`.
Старий фільтр іде на **власній** копії стану (пересів щоблоку — −21 dBFS), обидва — в одному циклі.
Правка під час фейду — одна відкладена, остання перемагає (≤ 40 мс). Так само — вмикання смуги (з нуля),
кнопка EQ, пресет, `hp_hz`. Замір [fidelity]: −83…−107 dBFS на 48 і 192k; зараз на 192k −32…−65.

### 2.4. Сабсонік, width

BW4: HP-секції з Q 0.5412 і 1.3066; на 40 Гц: −0.06 dB на 68 Гц, −0.67 на 50, −3.0 на 40, −10.4 на 30.
Нижче порту фазоінвертора (SC-G101 — від 68 Гц, не перевірено) енергія — струм без звуку.
Width/mono-bass без змін, side-HP на SVF.

### 2.5. Вхідне підсилення g_e

```
V(p)   = D − 60·(1 − p/100) dB, p = 1…100;  p = 0 або mute → 0
target = 10^((trim + min(V(p), D − B))/20)                 // D — драйв, B — запас під EQ (§3)
g1 += (target − g1)·kv;  g2 += (g1 − g2)·kv;  x *= g2         // kv = 1 − exp(−1/(τ·fs)); τ 5 мс, mute 10 мс
if |g2 − target| ≤ 1e-6·target + 1e-9:  g1 = g2 = target
```

Замір [fidelity]: unmute −76 dBFS (зараз −42), крок 0.6 dB −100 (−66), крок 6 dB −82 (−48).

### 2.6. Бас-лімітер

Два однакові LR4 (SVF, Q 0.7071): `det` на x, `app` на x із затримкою Lb — одна лінія затримки замість
двох (7.9 проти 15.4 KB на 192k), результат бітово той самий.

```
A: (bp1, lp1) = SVF(x);  ap = x − 2k·bp1;   B: lp = LP(lp1);   hp = ap − lp
det, кадр:  ph = max(ph,|hpL|,|hpR|);  pl = max(pl,|lpL|,|lpR|);  Eh += hpL²+hpR²;  El += lpL²+lpR²
app, кадр:  y = fmaf(gb − 1, lp_d, ap_d);  gb += dgb
вузол (ph, pl — максимум цього й попереднього чанка):
   req = (ph + pl ≤ Tb або pl = 0) ? 1 : clamp((Tb − ph)/pl, Gmin, 1)      // Tb = −0.5 dB, Gmin = −12 dB
   якщо Pc > 0:  Ph += (Eh/D − Ph)·kp;  Pl += (El/D − Pl)·kp;  kp = 1 − exp(−D/(0.05·fs))
                 якщо Pl > 0: req = min(req, clamp((√Pc − √Ph)/√Pl, Gmin, 1));  Pc = 10^(cap_dB/10)
   далі — огинаюча 2.7: Mb = round(0.005·fs/D), hold 50 мс, release 200 мс, Lb = (Mb+1)·D
```

LR4-смуги синфазні, тож `ap − (1−g)·lp` монотонна між g і 1. На +6 dB над стелею [protection,
симуляція]: розгойдування 1 кГц 0.46 dB (повносмуговий 6.2, зараз 7.3), середина −0.04 dB, струм БЖ
4.6 → 2.4 А. `bass_xo_hz = 0` знімає стадію разом з алпасом; зміна xo — через mute-рампу 10 мс.

### 2.7. Брикволл

```
D = 8 | 16 | 30 кадрів (fs ≤ 50k | ≤ 100k | вище; ділить 240);  M = 9;  L = (M+1)·D
кадр:  cmax = max(cmax, |l|, |r|);  вихід = лінія[−L]·g;  g += dG;  кожні D кадрів: вузол(cmax), cmax = 0
вузол(P):  r = 1/max(1, P, Pprev);  Pprev = P;  кільце rh[M+1] ← r;  h = min(rh)
   if h ≤ held            {held = h; cnt = HOLD}
   elif h ≤ held·1.0593   {cnt = HOLD; h = held}         // той самий пік ±0.5 dB
   elif cnt > 0           {cnt−−; h = held}
   else                   {held = h}
   grel = h < grel ? h : grel + (h − grel)·kr;  if grel > 1 − 1e-6: grel = 1
   кільце gh[M] ← grel;  G0 = G1;  G1 = Σgh/M (свіжа сума — без дрейфу);  g = G0;  dG = (G1 − G0)/D
HOLD = round(0.040·fs/D);  kr = 1 − exp(−D/(0.25·fs))
```

Гарантія `|y| ≤ 1` — з опуклості: кожне вузлове значення, що торкається кадру, ≤ 1/пік кадру. Хост
[realtime]: 0 перевищень за 20 с ворожого сигналу на 44.1–192k (деке з біжучою сумою — 4…275),
THD+N ≤ −148 dB. soft_clip прибрано.

### 2.8. Вихід, вартовий, затримка, спектр

```
scale = k_out·2³¹;  k_out = 10^(T_dBFS/20)                    // сирий калібрувальний тон: k_out = 1
bad |= (v != v);  v = fminf(fmaxf(v, −1), 0.999999f);  q = (int32_t)(v·scale);  out = q ? q : DAC_KEEPALIVE
кінець блоку: |s| < 1e-15 → 0 у станах;  bad або !(|s| ≤ 1e6) → блок = keepalive, reset, audio.dsp_faults++
```

- NaN у `fcvt.w.s` RISC-V дає 2³¹−1 — повну постійну на TPA3255; сьогоднішня `f32_to_i32` її пропускає.
- Затримка 6.7–7.1 мс — у `set_consumer(prime, tx_queue_frames + BLOCK + dsp_.latency_frames())` і в
  `retune()` (AirPlay читає її). Індикатори рівня — від стелі.
- Спектр — задача ядра 1, пріоритет 4: моно-сума, усереднена в 1/2/4 рази, кільце в PSRAM, FFT 1024
  47 разів/с — 2.1 % замість 16.7 % в одному блоці 192k.

## 3. Рівні

- PCM5102A: 0 dBFS = 2.1 Vrms = 2.97 Vpk, похибка до ±6 % FSR (§8.5).
- TPA3255: G = 21.5 dB (×11.89), RIN 20 кОм, ≤ 7 Vpp (§7.5), PVDD 18–53.5 В (§7.3). Напівмости
  «identical, independent» (§9.1), INPUT_A живить лише напівміст A (Pin Functions); вихід до рейок
  (§9.4.1.2) — пік ≈ 0.95·PVDD з R_DS(on) 85 мОм і фільтром.

| вхід модуля | пік на колонці | кліп C | макс. на 6 Ом |
|---|---|---|---|
| SE з ЦАП на INPUT_A, INPUT_B на землю — «прямо на вхід» (CONCEPT §5) | ≤ 0.95·PVDD/2 | −9.8 dBFS | ≈11 Вт |
| SE → диференційний ×2 на ОП, як TPA3255EVM (SLOU441 §2.1, §2.3) | ≤ 0.95·PVDD | −9.8 dBFS | ≈44 Вт |
| SE → диференційний 0 dB | ≤ 0.95·PVDD | −3.8 dBFS | ≈44 Вт |
| інший каскад G dB | — | −9.8 − (G − 6) | — |

Обидві поширені схеми кліпують в одній точці, тому **типово C = −9.8 dBFS** (`audio.amp_clip_db10 = −98`,
`audio.amp_cal = false`) — CONCEPT §5 плюс даташит, не здогад. Для третьої схеми це 6 dB зайвого запасу
до калібрування — безпечний бік. Просідання PVDD: 22 В → C −0.75 dB.

- Поріг T_dBFS = min(C − 0.5, −1.0), типово −10.3 dBFS (`k_out` 0.305): 0.5 dB — на просідання й нагрів,
  −1.0 — межа міжсемплових перевищень ЦАП.
- Гучність 0.6 dB на %, 100 % = T + D; драйв D 0…6 dB, типово 0 (смак: гучність проти тихого
  бас-лімітування найгучніших мастерів).
- Запас під EQ — стеля гучності (Android LVM), не preamp: `B = max(0, trim + max|H_eq·H_sub|dB +
  20·log10(max(1, width)))` на [f_lo, min(20 кГц, 0.49·fs)], f_lo = 2·xo з бас-лімітером, інакше 20 Гц;
  64 лог-точки + f0 смуг + 8 кроків золотого перетину (~35 тис. тактів на правку) → `audio.eq_headroom_db`.
- EQ замовника: B = 3.5 dB (пресети 0.2…11.1): на 100 % піднятий EQ — рівно в стелі, верхні ~6 % шкали
  пласкі (позначка на шкалі); нижче стелі EQ on/off — один рівень, A/B чесний.
- Шум: ЦАП −112 dBFS (5.3 мкВ) плюс 85 мкВ TPA3255 (§7.6) — ~100 dB до максимуму; послаблення в цифрі
  SNR не з'їдає, атенюатор і дизер не потрібні.

## 4. Захист підсилювача

| механізм (SLASEA8A) | поріг | поведінка | при 24 В |
|---|---|---|---|
| кліп | вище C | імпульси на 1/4 fPWM, CLIP_OTW, сам знімається (§9.4.1.2) | певний: 100 % зараз на ~10 dB вище C |
| UVP PVDD | 14.5 В, гіст. 1.4 (§7.5) | Hi-Z, сам відновлюється (§9.4.1) | якщо БЖ не тягне: синус на межі, 2 канали ≈4 А (один напівміст ≈1 А), кліпований бас до 2× |
| CB3C → OLP | 12.9–17.0 А (табл. 4), 2.3 мс | до /RESET | лише < ~1.5 Ом або OC_ADJ поза діапазоном |
| OTW / OTE | 120 / 150 °C (§7.5; §9.3.1 — 125) | OTE до /RESET | лише малий радіатор |
| DC | 1.5 А (§9.4.1.3) | вимикає канал | клема на землю |

/RESET і XSMT — одна лінія GPIO34: кожен mute/unmute і зміна джерела знімає фіксовані збої.

Відповідь ланцюга — блоки 2, 5, 6, 7 і B; без кліпу зникає й подвоєний струм. Лог 0.5 с: мінімум GR
бас/пік за вікно, кадри на стелі, затискач, `dsp_faults`.

**Калібрування (~10 хв, мультиметр, телефон).** Екран «Підсилювач: калібрування» або `audio.tone_*`:
сирий тон повз ланцюг, k_out = 1, краї сплесків 5 мс, автовимкнення 60 с.
0. PVDD — DC вольтметр на клемах живлення в спокої; струм — з етикетки БЖ.
1. 60 Гц, −26 dBFS, лівий, потім правий канал: AC V **між** клемами колонки (жодну клему — на землю, BTL).
2. Той самий тон, AC V від кожної клеми до GND: обидві ≈ V/2 → Vmax = 0.95·PVDD; одна ≈ V, друга ≈ 0 →
   один напівміст, Vmax = 0.95·PVDD/2. `C = −26 + 20·log10(Vmax/(1.414·V))`, менше з двох каналів.
   Сам крок 1 не розрізняє 1-й і 3-й рядки таблиці §3 (обидва 1.25 В).
3. 100 Гц, сплески 250 мс через 750 мс, по черзі C − 1 і C + 1 dB (~100 дБ, коротко): +1 хрипить (FFT
   телефона: 3-тя гармоніка +20 dB) або світить CLIP-світлодіод, −1 чисто. Хрипить і −1 → C −0.5 до
   чистого; чисто й +1 → C +0.5 (до +1.5).
4. 60 Гц, обидва канали, C − 0.5 dB, 3 с, вольтметр на PVDD: провал, блимання БЖ чи просідання > 2 В →
   `audio.rms_cap_db10 = −30` і повтор кроком −10; менше — C += 20·log10(PVDD_навант/PVDD_спокій).
5. `audio.amp_clip_db10 = round(10·C)`, `audio.amp_cal = true`.
Без вольтметра: крок 3 наростанням від −16 dBFS по 0.5 dB; C = рівень першого хрипу − 0.5 (±1 dB).

Ключі — маніфест `modules/audio`, persist (не board.json: калібрування ітеративне, без перепрошивки):

| ключ | типово | діапазон |
|---|---|---|
| `audio.amp_clip_db10` / `audio.amp_cal` | −98 / false | −240…0 |
| `audio.drive_db` | 0 | 0…6 |
| `audio.hp_hz` / `audio.bass_xo_hz` | 40 / 120 | 0, 20…80 / 0, 60…250 |
| `audio.rms_cap_db10` | 0 = вимк. | −120…−10 |
| `audio.tone_mode` / `_db10` / `_ch` (не persist) | 0 / −120 / 3 | звичайний, сирий, сплески |

Якщо спрацює знову: лише хрип/CLIP → крок 3; провали, що минають самі → БЖ/UVP, RMS-стеля; тиша до
паузи чи зміни джерела → OLP/OTE (§8); клацання реле → плата модуля.

## 8. Що лишається невідомим

1. Вхідна схема модуля — кроки 1–2 (або фото: 8-вивідний ОП біля входу — схема EVM). Якщо гойдається один
   напівміст, модуль дає чверть потужності (≈11 Вт на 6 Ом); перетворювач SE → диференційний на ОП дає 4× —
   рішення по залізу за замовником.
2. Кліп під навантаженням, просідання PVDD, БЖ — кроки 3–4 і етикетка; який саме «захист» — симптоми §4.
3. OC_ADJ (вивід 7) — маркування або омметр без живлення: 22–30 кОм — CB3C, 47–64 кОм — фіксований OC,
   поза діапазоном — мінімальний поріг (табл. 4). Радіатор після 10 хв гучно — дотик чи ІЧ-термометр.
4. Порт SC-G101: свип 20–120 Гц на −30 dBFS, EQ вимк.; де дифузор ходить найменше, а порт дме найсильніше —
   Fb; `audio.hp_hz = round(0.7·Fb)`.
5. Чи виведені FAULT (вивід 19) і CLIP_OTW (21) — для PCF8574 (CONCEPT §2): автоматичний /RESET, перевірка
   калібрування онлайн, −3 dB на OTW, як радить TI (§9.3.1).
6. Латентності FPU P4 v1.3 і ціна субнормалів — `audio.dsp_bench`.

## 9. Оцінки архітекторів

| дизайн | якість 40 % | захист 25 % | CPU 20 % | ризик 15 % | разом |
|---|---|---|---|---|---|
| realtime | 7 | 6 | 9 | 9 | **7.45** |
| fidelity | 9 | 5 | 7 | 7 | **7.30** |
| protection | 7 | 8 | 5 | 6 | **6.70** |

- **realtime** — найчесніший бюджет (objdump, модель, FFT з дедлайну, NaN → постійна), лімітер без дрейфу;
  у захисті лише слот бас-лімітера й калібрування осцилографом, без типової стелі; рампа 1 мс лишається (−42 dBFS).

  −4.0 dBFS хибна для SE-входу — ~6 dB кліпу до калібрування.
- **protection** — найкращий розбір захистів і бас-лімітер під сценарій замовника, правильна стеля; але
  15.4 KB внутрішньої RAM, драйв 3 dB типово, модель БЖ на неперевірних ККД і psu_a.
- Усі троє вважали, що SE-вхід дає повний розмах BTL, і рахували C лише з підсилення — звідси крок «схема».

## 12. Тонкомпенсація і підйом порту (03.10.2026)

Замовник після прошивки DSP v2: колонки дають гарний панч, але немає глибокого м'якого басу,
«навіть на мінімальній гучності»; «бас на максимум» додає лише гудіння. Колонки — Denon SC-G101:
2-смугові, вуфер 13 см, фазоінвертор із портом ззаду, нижня межа 40–45 Гц (дані продавців:
son-video.com, hifi-guide.com, hifi-galerie-hamburg.de; паспорта Denon немає).

Три причини, і лише одна — тракт: (1) на малій гучності низ губить вухо — за ISO 226 при 50 фон
проти 85 на 40 Гц бракує ~15 дБ відносно 1 кГц; (2) 30–40 Гц 13-см вуфер у малому корпусі фізично
не дає, нижче порту він лише хрипить; (3) смуга EQ 62 Гц на +12 разом із сабсоніком 40 Гц дає
+12 дБ на 60–70 Гц і −7 на 30 — гудіння однієї ноти, а не глибина. Сабсонік 40 Гц для цих колонок
якраз на своєму місці (трохи нижче порту) і лишається.

### 12.1. Тонкомпенсація (`DspChain::set_loudness`)

Різниця контурів ISO 226:2003 між рівнем прослуховування і 85 фон на верху шкали:
D(f, a) = [Lp(f, 85 − a) − Lp(1k, 85 − a)] − [Lp(f, 85) − Lp(1k, 85)]. Дві полиці RBJ з
підсиленнями K·a, підігнані `tools/eq/fit_loudness.py` (Левенберг–Марквардт, вага від 40 Гц,
відносно 1 кГц, верхня полиця Q ≤ 0,71, корінь ≤ 10 кГц і рівна вище 12,5 кГц — далі шум і
артефакти кодеків, не музика): 148,6 Гц Q 0,359 K 0,5605; 10 кГц Q 0,71 K 0,2253.

| a, дБ під верхом | 10 | 20 | 30 | 40 | 50 |
|---|---|---|---|---|---|
| найбільше відхилення від контурів (≥ 40 Гц, відносно 1 кГц) | 0,37 | 0,75 | 1,13 | 1,50 | 1,78 |

Рішення:
- **Опора рухається з B.** a = 60·(1 − гучність) − B: верх шкали — drive − B, тож з підйомом EQ
  опора опускається разом із ним. Полиці піднімають щонайбільше 0,5605·a < a, отже на будь-якій
  гучності ніщо не перевищує того, що грає 100 %; тест проганяє гучність 1…100 % з повношкальним
  синусом на 50 Гц, 1 і 12,5 кГц, з EQ і без — брикволл не торкається.
- **a ≤ 50 дБ** (35 фон, фонова музика): далі компенсація не росте.
- **Ковзання, а не стрибки.** Підсилення полиць іде до цілі одним полюсом τ 50 мс, коефіцієнти SVF
  — прямою всередині блоку (`svf_stereo_ramp`): стрибок коефіцієнта на межі блоку — це сходинка у
  виході, тик на басовій ноті. Тест: гучність 20 → 80 → 20 % крок на блок під нотою 60 Гц — над
  2 кГц −107,6 dBFS з тонкомпенсацією проти −112,0 без.
- **Дріт.** На верху шкали, вимкнена і після повернення до 0 дБ — стадія пропускається, вихід
  біт-у-біт той самий (тест).
- **Дизайн у float, білінійний**, щоблоку під час ковзання: на 149 Гц однаковий на всіх частотах
  дискретизації, на 10 кГц різниця 44,1 і 192 кГц — 0,6 дБ на 16 кГц. Виміряно в ланцюгу: від
  контурів 0,59 дБ (48 кГц) і 1,10 дБ (192 кГц) при a = 30.
- Типова сила 70 %: 100 % гучності на панелі гучніше за 85 дБ SPL на місці слухача, тож повна
  компенсація була б завеликою на середній гучності.

### 12.2. Підйом порту (`DspChain::set_port`)

Модель фазоінвертора (Small, з втратами QL = 7; SPL і хід дифузора), порт 50 Гц, три вирівнювання:
B4, QB3-подібне (передемпфоване) і «бумкаюче» (Qt 0,5). Кандидати порівняно з нинішнім
сабсоніком BW4 на 40 Гц за F3, горбом АЧХ і найбільшим ходом дифузора:

| фільтр | B4: F3 / хід | QB3: F3 / хід | Qt 0,5: F3 / горб / хід |
|---|---|---|---|
| BW4 40 Гц (було) | 58 Гц / 0 дБ | 79 / 0 | 50 / +1,1 / 0 |
| BW4 0,8·fb + пік fb +3 дБ Q 1,4 | 49 / +1,7 | 70 / +1,3 | 46 / +2,6 / +1,6 |
| BW4 0,8·fb + пік fb +4 дБ Q 1,4 | 48 / +2,3 | 66 / +1,8 | 45 / +3,3 / +2,2 |
| BW4 0,8·fb + пік fb +6 дБ Q 1,4 | 45 / +3,5 | 55 / +2,8 | 43 / +4,8 / +3,4 |
| BW4 0,8·fb + пік fb +4 дБ Q 1,0 | 48 / +2,9 | 63 / +2,4 | 45 / +3,7 / +2,8 |
| BW4 0,7·fb + пік fb +4 дБ Q 1,4 | 47 / +4,8 | 66 / +5,0 | 44 / +3,4 / +3,6 |
| ФВЧ 2-го порядку fb Q 2 + BW4 0,6·fb (B6) | 45 / +4,0 | 52 / +3,1 | 43 / +5,7 / +4,7 |

Вибрано BW4 на 0,8·fb + пік на fb, Q 1,4: найменший хід на децибел підйому — пік лягає в мінімум
ходу дифузора на fb. Типово +3 дБ, а не +4: на «бумкаючій» коробці підйом додає горба, тобто
гудіння. Поки порт задано, `audio.hp_hz` не діє. Пік входить у запас B (тест: B 3,46 дБ = верх
аналогової кривої), з бас-лімітером на 120 Гц — 0,28 дБ, решту той поглинає. Вмикання —
кросфейдом сабсоніка (80 мс): −83,5 dBFS над 500 Гц під нотою 62 Гц. У ланцюгу АЧХ збігається з
аналоговим прототипом до 0,0001 дБ.

### 12.3. Ціна і що далі

Три секції SVF (дві тонкомпенсації, одна порту), за оцінкою ~1,6 % ядра на 96 кГц; під час
ковзання тонкомпенсація вдвічі дорожча. Перевірити на стенді `audio.dsp_pct` / `dsp_max_pct`.
Нова веб-картка «Бас і тонкомпенсація» живе в `ui.json`, тобто в розділі `data`: потрібна повна
прошивка (`userdata` вона не чіпає). Далі: вимір частоти порту бортовим мікрофоном (ближнє поле
біля дифузора: мінімум = fb) і пошук кімнатних мод.

### 12.4. Частота порту — мікрофоном панелі (03.10.2026)

Замовник: «у нас на платі є мікрофон, хоч не калібрований» (ES8311 + MEMS, `MIC_CAPTURE.md`).
Метод — ближнє поле (D. B. Keele, JAES 22(3), 1974): за сантиметр від дифузора мікрофон чує сам
дифузор, а дифузор фазоінвертора на частоті порту майже стоїть — рухається повітря в порту. Отже
в ближньому полі на fb вузький провал: вище — підйом до смуги, нижче — підйом дифузора, що
розвантажився. Калібрування мікрофона не потрібне: шукається положення провалу, не рівень.

- `components/audio_dsp/port_finder.{h,cpp}` (чиста арифметика): `ToneMeter` — синхронне
  детектування одного синуса у вікні Ганна 0,4 с (фазори у float, перенормування кожні 256
  відліків; гул за 10 Гц пригнічується на −134 дБ); `find_port()` — шум віднімається за
  потужністю, крива згладжується по трьох точках, провал = локальний мінімум, від якого крива
  піднімається ≥ 6 дБ в октаві вище і ≥ 1,5 дБ в октаві нижче (підйом знизу буває малим, а в
  закритої колонки його немає зовсім); місце — вершина параболи по незгладжених точках у
  log-частоті. OK — 10 дБ вище, 3 дБ нижче і 10 дБ над шумом; інакше «сумнівно». Сітка — цілі герци
  20…100 через ~1/24 октави (тон приймає цілі), без 50 і 60 Гц (мережевий гул на них синфазний із
  тоном — потужності не складаються).
- Перевірено на моделі (Small; B4, QB3-подібна, «бумкаюча»; fb 35…70 Гц; із фільтром мікрофона
  40 Гц і без; гул 50 Гц і шум, кожне вікно — повна симуляція в часі): без звуку порту в мікрофоні
  — найгірше 0,75 Гц від fb; звук заднього порту на 5 % рівня дифузора тягне провал донизу до 3,2 %;
  гул −40 дБ просто біля провалу його не зсуває (±1,5 Гц); закрита колонка — «провалу нема»;
  тиша — «не чує». `tests/host/test_port_finder.cpp`.
- На панелі — `components/mic_capture/src/mic_input.cpp` (ініціалізація ES8311 → I2S2 з
  діагностики, лише на час виміру) і `AudioModule::port_meter_loop()` в окремій задачі (ядро 0,
  стек 8 КБ, буфер вікна 77 КБ у PSRAM): джерело «вимкнено», 1 с прогріву кодека, 6 вікон тиші
  (шум на кожній частоті сітки), тест-тон raw на обраному каналі, рівень під 90 Гц — до −20 дБ
  шкали мікрофона в межах −60…−30 dBFS (−10 дБ при кліпі), далі 50 точок по 0,68 с. ~45 с усього,
  менше за 60-секундний ліміт raw-тону. Усе — через ключі модуля, тож веб показує, що відбувається;
  джерело й тон повертаються в будь-якому разі. Впевнений результат у 30…80 Гц пишеться в
  `audio.port_hz`. Стан — `audio.port_meas_status` (рядок SharedState: 64 байти, тож коротко),

  67,7 Гц, 17 дБ зверху, 4 дБ знизу, 57 дБ над шумом, тоді — OK і записано само. Крива росте
  ~20 дБ/октаву від 20 до 50 Гц: так погано чує низ сам мікрофон, а не колонка. Палець на
