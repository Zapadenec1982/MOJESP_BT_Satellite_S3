# LHDC V5 and 96 kHz integration

Customer request: add WillyBilly06/LHDC-V5-Decoder and 96 kHz (the customer
explicitly corrected the initial "92 kHz" request). AUX remains out of scope.

## Provenance and scope

- Upstream: https://github.com/WillyBilly06/LHDC-V5-Decoder
- Pin: `676af03d2b7a2ed5c1f9bdca7bf8938cc85f704b`.
- `components/lhdcv5_decoder/decoder/`, component CMakeLists and README are
  byte-identical to that revision. README explicitly states Apache-2.0; a copy
  of the standard license text is supplied. No upstream IDF tree, application,
  binary, proprietary encoder or LDAC decoder was imported.
- Reference A2DP headers/CIE code were adapted in `bt_overlay`. The packet
  wrapper was rewritten around the existing checked RTP stripper and bounded
  PCM capacity. The decoder math remains upstream code, not locally validated
  against a proprietary reference decoder.
- Stock shared ESP-IDF remains unchanged at v5.5.5,
  `b774170ff46c393eeb5e495ea37936038d3f4f4f`.
- Patch 0003 adds the optional decoder dependency, Kconfig option, source files
  and one AVDTP endpoint. `setup.ps1 -Clean` reproduces the local BT component.

## Negotiated formats

LHDC V5 vendor `0x0000053a`, codec `0x4c35`, CIE LOSC 13. Stereo, 44.1/48/96 kHz,
16/24 source bits, 5 ms framing. Do not advertise 192 kHz, 32-bit source,
low latency, spatial processing, metadata or lossless extensions. Single-core
decode is retained (`LHDC_DEC_DUAL_CORE=0`, as upstream); no PSRAM is assumed.

Protocol 1.4 adds codec ID 5 and host capability bit 5 for 96 kHz. It is valid
only with minor >=4, RELOCK and FORMAT_READY. Old/missing/incomplete HELLO never
enables 96 kHz. Endpoint policy is frozen before A2DP initialization, as for
48 kHz in the existing firmware; after upgrading the host, restart the satellite.
If a replacement host loses 96 kHz capability during a stream, PCM is gated.
It can resume after a capable host returns and acknowledges a fresh transaction.

Native PCM: 16-bit content uses 16-bit slots with a modern host; 24-bit content
uses 32-bit containers. Existing legacy wide/narrow compatibility is preserved.
No new width conversion, sample-rate conversion, GPIO or amplifier-mute change.

## Adapter checks and lifetime

- Parse selected CIE as one supported rate/depth; reject cached unsupported
  configurations and unsupported optional features. Capability negotiation
  intersects the peer rates with the actual host policy.
- Checked RTP handles CSRC, extension, padding and packet length. Fragment
  reassembly is limited to 3072 bytes and requires sequential RTP sequence
  numbers/counts. Reset/cleanup clear partial fragments and decoder history.
- Preserve the upstream over-the-air framing: media header, then one LHDC marker
  byte before the self-delimiting encoded frames. Nonfragmented count==0 is legal.
- BTC's existing 4096-byte default scratch fits one 96 kHz stereo frame:
  480 samples/channel * 2 * 4 = 3840 bytes. Pass capacity in samples/channel
  according to the configured native width, never an unconditional 1920.
- Validate consumed bytes, generated samples, channels, rate and PCM width before
  publishing. Invalid configuration/allocation failure leaves the decoder muted.
- Workspace and rate-sized tails are freed on codec exit; repeated init/configure
  does not discard live pointers. Global IMDCT/window/entropy allocations are freed.

## Espressif checks and paired P4 fix

Checked local target-specific `soc_caps.h`: ESP32 has Classic BT/APLL, P4 has
I2S/APLL. Read version/target-correct I2S docs:
https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32p4/api-reference/peripherals/i2s.html
and exact IDF `i2s_std.c`, `hal/esp32p4/clk_tree_ll.h`, plus the existing
`i2s_clock.h` arithmetic and tests. No revision-3-only clock is introduced.

At 96 kHz / 32-bit stereo the slave's internal MCLK is 49.152 MHz. IDF needs
the source above 1.99 times that. The existing P4 output plan uses MCLK x512,
APLL 98.304 MHz, below the documented 125 MHz maximum; output remains 96 kHz.
96 kHz / 16-bit RX also needs APLL (49.152 MHz source at output MCLK x256).

Found and fixed a latent transition bug: AudioModule parked the RX off APLL only
when its slots were 32 bits. That misses 96 kHz / 16-bit RX and prevents the
master from retuning afterward. Both format changes and source exit now always
request the safe 48 kHz / 16-bit park; the driver skips unchanged formats.
The existing FORMAT_READY barrier still covers the entire transition.

## Validation and remaining bench work

Host tests compile the actual CIE adapter, RTP wrapper and portable decoder.
They cover rate/depth masks, disabled optional modes, old-host rate fallback,
108 alternating rate/depth configurations, repeated teardown, malformed RTP,
missing/oversized fragments and undersized PCM output. The existing HELLO replay
also checks bit-5 prerequisites and older protocol minors.

These are boundary/lifetime tests, not an audio-fidelity proof. Upstream's
encoder roundtrip needs a proprietary encoder library that was not imported.
Host allocation success does not establish internal-heap headroom or real-time
decode performance on WROOM. The customer confirmed the phone can select
LHDC V5 and 96 kHz. Before declaring bench success, capture both boards and verify:

1. HELLO 1.4 / host caps 0x39; LHDC V5 96000 Hz and correlated READY before PCM.
2. Clean sustained 96 kHz playback, stable queues and no output drops/panic/WDT.
3. 96 -> 48 -> 96 and LHDC -> SBC -> aptX HD -> LHDC without reconnect.
4. Pause/resume, phone reconnect and both reboot orders.

Build/test results and flashed ELF identities are recorded in the paired handoff.
